# S5 原型与 HTML 交付 —— 给人看的那一份

> 阶段定位：PRD.md 是给评审和施工看的；原型与 HTML 是给**拍板的人**看的。这一步不产生新需求，只换表达形态。
> 上游：`04_PRD八项要求.md`。下游：`06_自查与交付.md`。

## 一、目标与判据

**目标**：让一个不读 Markdown 的人，打开一个离线 HTML 就能看懂「这个工具长什么样、点哪里、发生什么」，并且能对回 PRD 的功能点编号。

**判据（全过才算完成）**：

| # | 判据 | 判定方式 |
|---|---|---|
| 1 | 每个 F-xx 至少被一张原型图覆盖，图上标了 F 编号 | 交叉比对 F 清单与图注 |
| 2 | 原型图上不出现 PRD 里没有的按钮/字段 | 逐个控件回查 §6 |
| 3 | HTML 单文件、断网可开、无外部引用 | 断网打开；搜 `http://` `https://` `src=` `@import` |
| 4 | SVG 内嵌在 HTML 中，⛔ 不作为图片外链 | 搜 `<img` 与 `xlink:href` |
| 5 | HTML 与 MD 内容同源（标题、编号、AC 文案一致） | 抽 3 条 AC 比对 |
| 6 | 每张图下配「原型说明」并标出对应 F | 逐图检查 |

**⛔ 本阶段不做什么**：

- 不写交互逻辑、不接数据、不做可点击原型（只做静态示意）。
- 不引 CDN、外链字体、外部 CSS/JS；不塞 base64 大图。
- 不在 HTML 里"顺手优化"PRD 措辞——要改回 S4 改 MD，再重新生成。
- 不画 PRD 没有的界面（想象出来的页面等于偷偷加需求）。

## 二、操作步骤

1. **拉 F 清单**。把 §6 的 F 编号全部列出来，标出"有界面 / 无界面（后台任务、命令行）"。无界面的不画图，只在 HTML 里给一条说明。
2. **定图数**。一个主流程一张主图；复杂页面按 tab/步骤拆，单张图不超过 3 个区块。⛔ 不为凑数画重复图。
3. **画 SVG**。画法与配色照 `00_PRD编写规范.md` §五（原型图）或 §四（业务流程图）。两类别混：原型图是"界面长什么样"，流程图是"状态怎么走"。
4. **标编号**。每张图左上角标 `原型 P-01`，图下说明写 `对应 F-01 / F-02`。
5. **写原型说明**。三段：这张图在解决什么（一句话）、关键控件清单（控件名 → 对应 F）、本图不包含什么。
6. **生成 HTML**。按同文件 §六 出单文件：内联 `<style>`、SVG 内嵌、左侧目录 + 右侧正文、页脚注明"按 PRD 编写规范产出"。
7. **自检引用**。`grep -nE "https?://|@import|<img" PRD.html` 应为空（`lang="zh-CN"` 的 xmlns 不算外链）。
8. **写盘**。Python `write_text(html, encoding="utf-8", newline="\n")`，纯 LF。

## 三、输出模板

**原型说明（图下固定格式）**：

```markdown
### 原型 P-01 导入主界面

- 解决什么：让运营一眼看到"能不能导、导了多少、哪条失败"。
- 关键控件：
  | 控件 | 文案 | 对应 |
  |---|---|---|
  | 主按钮 | 开始导入 | F-01 |
  | 失败清单 | 第 3 条失败：链接无效 | F-04 / E-02 |
  | 进度条 | 已完成 32/50 | F-05 |
- 本图不包含：权限申请弹窗（见 P-02）、设置页（本期不做）。
```

**HTML 交付检查表（贴进交付说明）**：

| 检查 | 命令/方式 | 结果 |
|---|---|---|
| 单文件 | 文件数 = 1 | 是 |
| 无外链 | `grep -nE "https?://|@import"` | 空 |
| 无外图 | `grep -n "<img"` | 空 |
| 断网可开 | 断网双击打开 | 正常 |
| 与 MD 同源 | 抽 3 条 AC 比对 | 一致 |

## 四、反例

**反例 1：外链 CDN**

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@5/dist/css/bootstrap.min.css">
```

错在哪：断网打开就是白板；内网环境直接加载失败；且违背规范"单文件自包含"。原型 HTML 的生命周期比 CDN 版本长，两年后链接大概率 404。

**反例 2：原型偷偷加需求**

```
PRD §6 只有「开始导入」「失败清单」两个控件，原型图上多出「定时任务」「批量重试」「导出报表」三个按钮。
```

错在哪：看图的人会以为这些都要做，评审时按图提问、按图排期，最后 PRD 与实现永久对不上。图上每多一个控件，就等于多一条未评审的需求。

**反例 3：SVG 存成外部图片**

```html
<img src="./原型1.svg">
```

错在哪：拷贝 HTML 给别人时图片丢了；单文件自包含被破坏。必须把 `<svg>` 直接写进 HTML。

**反例 4：只给 HTML 不给原型说明**

```
（一张大图，图下无任何文字）
```

错在哪：看图的人不知道哪个控件对应哪条 F，评审无法落到条款；也失去了"图与 PRD 同源"的可核性。

## 五、衔接条件

**进入 S6 的条件**：

1. 判据 6 条全过（尤其"断网可开"与"无外链"两条要留命令输出）。
2. F 清单 100% 被覆盖或有"无界面"说明。
3. HTML 与 MD 的编号、AC 文案抽检一致。

**交接物**：`原型.html`、`<项目名>_PRD_v1.0.html` + HTML 检查表。S6 的自检第 8 条（HTML 单文件可离线打开、SVG 无外部引用）直接引用本阶段留下的检查结果，⛔ 不重复跑一遍就写"通过"。

**回退条件**：画图时发现某个 F 无法画出界面（说不清展示什么） → 退回 S4 补 F 的「展示内容」，⛔ 不在图上现编控件。
