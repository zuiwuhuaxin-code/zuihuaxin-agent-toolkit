# S1 需求澄清 —— 先复述理解，⛔ 不写 PRD

> 阶段定位：拿到需求原话后的**第一份产出**。它的唯一任务是让「我理解成的样子」和「你要的样子」当面对齐，⛔ 不是先出文档。
> 上游：无（本阶段是入口）。下游：`02_十个关键问题.md`。

## 一、目标与判据

**目标**：把一段口语化、跳跃、带隐含前提的需求，压成一张能被对方点头或摇头的四栏表，并给出 2~3 条粗方案路线，让对方判断"方向对不对"，而不是判断"细节好不好"。

**判据（全过才算完成）**：

| # | 判据 | 判定方式 |
|---|---|---|
| 1 | 四栏（要做什么 / 给谁用 / 什么场景下用 / 成功长什么样）无空格 | 逐栏检查，空栏即未过 |
| 2 | 粗方案 2~3 条，每条带「代价 + 风险 + 我倾向哪条及理由」 | 少任一要素即未过 |
| 3 | 回复中不出现任何 PRD 章节标题（产品概述 / 功能需求 / 验收标准…） | 搜标题关键词 |
| 4 | 用户明确回「对」或指出偏差 | 无回应不进 S2 |
| 5 | 全文一屏内（≤40 行） | 超长说明在做方案细节 |

**⛔ 本阶段不做什么**（写在回复开头，逐条列）：

- 不写 PRD 任何章节，哪怕对方催。
- 不做字段级设计（字段名、控件类型、校验规则都不给）。
- 不排期、不估工作量、不排优先级。
- 不判「这个需求成不成立」——那是 S3 的事。
- 不替对方补需求（「你应该是想要…」这句话只能出现在「需确认」栏里）。

## 二、操作步骤

1. **抄原话**。把用户的需求描述原样贴进回复顶部，⛔ 不改写、不润色。改写会让人以为你在替他说话。
2. **拆句**。按句号/分号切，逐句判定它落在四栏的哪一栏；一句落不进任何栏 → 它大概率是背景或情绪，记到「背景」里。
3. **填四栏**：
   - 要做什么：动词开头的动作句（「把 10 个渠道的选题批量生成草稿」）。
   - 给谁用：具体到角色（「运营小王」），⛔ 不写「用户」。
   - 什么场景下用：时间/地点/前置动作（「每天早上 9 点看完热点后」）。
   - 成功长什么样：可观察结果（「原本 2 小时的活 20 分钟干完，且不用手动复制」）。
4. **标不确定**。四栏里有任何一格是猜的，就地标 `【待确认】` 并写清猜的依据。
5. **给粗方案**。列 2~3 条路线，只到"用什么东西解决"这一层（例：路线 A 桌面工具；路线 B 浏览器插件；路线 C 半自动导出+人工）。每条写：代价、风险、我倾向哪条及理由。
6. **列 3 条以内「没听懂」**。这三条将作为 S2 问题清单的种子，⛔ 现在不追问超过 3 条，会把对方问烦。
7. **收尾句固定**：「以上理解如无偏差，我进入 S2 提 10 个问题；如有偏差请直接圈出错的那一栏。」
8. **等确认**。⛔ 用户没回之前不往下走；用户只回"继续"时，把【待确认】项并入 S2 问题清单。

## 三、输出模板

```markdown

|---|---|---|

### 2. 大致思路（只到"用什么解决"这一层）

|---|---|---|---|---|
| A |  |  |  |  |

```

## 四、反例

**反例 1：直接开写文档**

```
好的，我来写 PRD。
# 内容发布平台 产品需求文档 v1.0
## 1. 产品概述
## 2. 功能需求
```

错在哪：原文明确要求「先不要直接写 PRD」。一旦成文，用户只会去改字句，不会再去纠"你到底理解成了什么"；理解偏差从此藏在正文里，到 S6 也查不出来。

**反例 2：复述变成换词**

```
你要做一个内容发布工具，帮用户提升效率，实现自动化运营。
```

错在哪：把原话换成同义词不算复述。「提升效率」「自动化运营」都是不可判的空话，用户看不出你听懂了哪一步、漏了哪一步，等于没对齐。

**反例 3：思路写成技术方案**

```
建议采用三层架构：接入层用 Flask，任务层用 Celery，存储用 SQLite…
```

错在哪：这是 S4 之后甚至施工阶段的事。S1 给技术选型，会把"方向对不对"的讨论劫持成"技术好不好"的讨论，用户没有能力也没有必要在此刻判断。

**反例 4：替用户补需求**

```
你应该是想要每天早上自动抓取热榜并自动发布。
```

错在哪：「自动发布」四个字用户没说。这类补充一旦被默认接受，后面整条 PRD 都建立在一个没人确认过的前提上。正确做法：写进【待确认】，到 S2 变成一条问题。

## 五、衔接条件

**进入 S2 的条件（三条同时满足）**：

1. 用户已回「对」或已指出并纠正偏差，纠正后的四栏已重贴一次。
2. 四栏无 `【待确认】`，或 `【待确认】` 已登记进 S2 问题清单初稿。
3. 回复中确实没有出现 PRD 章节标题（自查一遍再发）。

**交接物**：四栏表 + 粗方案倾向 + 未听懂清单。S2 直接拿「未听懂清单」当第 1~3 号问题的种子。

**回退条件**：S2 提问过程中发现四栏有整栏错（不是细节错），退回 S1 重贴四栏，⛔ 不在 S2 里就地改理解。
