# S2 十个关键问题 —— 只提问，⛔ 不代答

> 阶段定位：把「我没搞清的」变成「你必须回答的」。这是需求澄清的真实机制：需求不是 Agent 编出来的，是从人的回答里逼出来的。
> 上游：`01_需求澄清.md`。下游：`03_需求分析报告.md`。

## 一、目标与判据

**目标**：提出 10 个（不足 10 个就如实少给）真正阻塞 PRD 的问题，每个问题都能回答一句话——**「这个问题答错了，我会把哪条需求写错」**。答不出这句话的，就是凑数。

**判据（全过才算完成）**：

| # | 判据 | 判定方式 |
|---|---|---|
| 1 | 数量 8~10 条；不足 10 条时附一句「为何少于 10 条」 | 数编号 |
| 2 | 每条都有「答错会写坏哪条需求」，且写的是**具体后果**（不是「影响体验」） | 逐条读 |
| 3 | 每条标注「必须你答 / 我可自查」，我可自查的不占 10 条名额 | 逐条读 |
| 4 | 问题之间不重复，不同问一件事的正反两面 | 交叉比对 |
| 5 | 前 5 条为阻塞级（不答就无法写 PRD） | 看排序 |
| 6 | 无一条替用户预设答案后当结论写 | 搜「应该」「显然」 |

**⛔ 本阶段不做什么**：

- 不硬凑数量。宁可交 8 条真问题，也不编 2 条废话占位。
- 不凭空臆断。问题里的前提必须来自 S1 的原话或既有文档。
- 不替用户回答，包括"先按 A 假设继续"。假设可以写，但必须挂在「待确认」栏。
- 不在提问阶段夹带方案定稿（「我准备用 A 方案，你同意吗」不是问题，是逼签）。

## 二、操作步骤

1. **建候选池**。按四个来源各拉 4~6 条，总数 ≥15：
   - 角色：谁用、谁不用、谁审批、谁受益但不出钱。
   - 边界：做到哪停、哪些明确不做、和既有系统谁管哪段。
   - 数据：数据从哪来、多大量、多久一次、删了要不要留痕。
   - 异常：失败怎么办、重复提交怎么办、权限不够怎么办、超时怎么办。
2. **先删「我可自查」**。能从既有文档、代码、事实底稿里查到的，自己去查，不进 10 条。查完仍不确定的，改写成"事实型提问"（「现有采集器是否已支持小红书？」）保留。
3. **再删「答了也不影响」**。对每条问一句：答 A 或答 B，写出来的 PRD 会有差别吗？没差别 → 删。这一步专杀凑数。
4. **给每条挂后果**。格式固定：`答错会写坏 → <编号> <哪一条> 的 <哪个字段>`。例：`答错会写坏 → F-03 的触发条件（会写成"每次打开就同步"，实际是手动触发）`。
5. **排序**。阻塞级（不答写不下去）排前 5，优化级排后 5。同级内按「影响多少条需求」降序。
6. **标默认假设**。必须给出「在你回答前，我暂按 X 处理」的，写进「暂定假设」栏，并标 `待确认`。⛔ 假设不能出现在正文结论里。
7. **交人回答**。一次性发全部问题，编号固定，⛔ 不一条条挤牙膏。
8. **回填**。用户答完，逐条把答案抄进「回答」栏并标注回答人；答得含糊的（「看着办」「你定」）追一次，仍含糊的进 S3「未决」。

## 四、反例

**反例 1：硬凑数量**

```
Q-08 是否需要登录？
Q-09 界面要不要好看？
Q-10 是否需要网络？
```

错在哪：三条都答不出「答错会写坏哪条需求」——登录在既有系统里已经确定，界面色系由 UI 规范定，"是否需要网络"在桌面工具语境下没有意义。这三条占了名额，真正的问题（比如"导入失败怎么算"）就挤不进去了。

**反例 2：问题里夹带答案**

```
Q-02 我建议单次限 50 条以防超时，你同意吗？
```

错在哪：这不是提问，是逼对方在两个都不了解后果的选项里点头。正确写法：「单次上限你想要多少？超过上限时期望是拒绝提交还是分批排队？（影响 F-01 操作规则 / E-03 超时处理）」。

**反例 3：把假设写成结论**

```
Q-05 导入失败后系统会自动重试三次。
```

错在哪：句号结尾的"问题"不是问题。用户没答，重试三次就变成了事实，再往下会污染 F 的系统反馈与 E 的异常处理。

**反例 4：十个问题问同一件事**

```
Q-01 导入失败怎么办？ Q-02 导入部分失败怎么办？ Q-03 导入全失败怎么办？ …
```

错在哪：三条其实是一个问题的三种情形，应合并为一条「失败粒度与回滚策略」，把腾出的名额给角色、权限、数据留存这些没覆盖的维度。

## 五、衔接条件

**进入 S3 的条件**：

1. 10 条（或 8 条 + 说明）已全部发出，编号稳定不再变动。
2. 用户已回填 ≥7 条；不足 7 条时，把未答项集中列成「S3 未决清单」并说明缺它会卡住哪一章。
3. 阻塞级 5 条必须全有答案（含"明确不答"），否则 ⛔ 不进 S3。

**交接物**：问题表（含回答与暂定假设）+ 阻塞级标记 + 未决清单。S3 报告的「问题回填」章直接引用本表，⛔ 不重新组织问题。

**回退条件**：S3 调查事实时发现某个回答与实测冲突（用户说"已有采集器"但实测目录是空的），把该条退回 S2 追加一问，并把冲突写进 S3 的「事实 vs 回答」对照。
