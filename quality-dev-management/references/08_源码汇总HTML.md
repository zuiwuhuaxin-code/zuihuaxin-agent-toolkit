# S8 源码汇总 HTML

> 位置：闭环完善之后，全流程最后一环。
> 本阶段唯一不可替代的价值：**把几百 KB 的源码变成一个人能打开的页面**——目录树可折、点名字能跳、每行有号、关键字有色、断网能看。

## 一、目标与判据

| 目标 | 判据（可观察） |
|---|---|
| 单文件 | 产物只有一个 `.html`；页面内 `<script` / `<link` / `src=` / `@import` 命中数 = 0 |
| 无外链资源 | 上一条已覆盖：`grep -cE '<script|<link|src=\|@import'` = 0（源码正文里的 URL 是转义后的纯文本，不算资源引用） |
| 可定位 | 左侧目录树含全部打包文件；每条 `href="#f-N"` 有对应 `id="f-N"` |
| 有行号 | 每行源码前有 `class="lnum"` 行号元素，且不可选中（复制不带行号） |
| 有高亮 | 至少覆盖注释 `c` / 字符串 `s` / 数字 `n` / 关键字 `k` 四类 CSS 类 |
| 内容保真 | 页面顶部统计注释 `source_pack: files=N lines=M` 与目录实有数一致 |
| 可读 | 单文件体积在可打开范围（建议 < 30 MB） |

## 二、输入

1. S7 之后的终版源码目录（绝对路径）。
2. 打包白名单（扩展名）与排除目录清单。
3. 项目名（作为页面标题）。

## 三、操作步骤

**H1 定白名单**
默认白名单：`.py .js .ts .tsx .jsx .java .go .rs .c .h .cpp .hpp .cs .php .rb .sh .sql .html .css .md .txt .yml .yaml .json .toml .ini .cfg`。按项目调整，⛔ 不打包二进制、图片、编译产物。

**H2 定排除目录**
默认排除：`.git`、`__pycache__`、`node_modules`、`.venv`、`venv`、`.idea`、`.mypy_cache`、`.pytest_cache`、`dist`、`build`。按需加 `--exclude`。

**H3 打包**

```bash
python scripts/source_pack.py <源码目录> -o 源码.html --title "<项目名>"
# 只打 python 与 markdown
python scripts/source_pack.py <源码目录> -o 源码.html --ext .py,.md
```

**H4 验证（四条，缺一不可）**

```bash
# 1 无外部资源引用（应输出 0）
grep -cE '<script|<link|src=|@import' 源码.html
# 2 统计注释（工具自报，拿它与目录实有数比）
grep -o 'source_pack: files=[0-9]* lines=[0-9]*' 源码.html
# 3 目录实有数（应与上一条的 files= 相等）
find <源码目录> -type f -not -path '*/.git/*' -not -path '*/__pycache__/*' | wc -l
# 4 体积
ls -lh 源码.html
```

⚠ 判据为什么用统计注释而不是数标签：源码正文里可能恰好出现 `class="lnum"` 这类字面量（尤其文档类文件），数标签会把正文误算进来。统计注释由打包器在生成时写入，是唯一可信的自报值，必须与磁盘实有数交叉核对。

**H5 人工过一遍**
浏览器打开（可断网）：点 3 个不同深度的文件跳转；折叠/展开两个目录；选一段代码复制，确认行号没被带进去。

**H6 写进交付说明**
打包了哪些扩展名、排除了哪些目录、文件数、总行数、体积、生成命令。

## 四、输出模板

### 4.1 页面结构（工具已实现，此处为核对清单）

```
┌──────────────┬────────────────────────────────────────┐
│ 目录树         │  文件路径 · 行数 · 体积                  │
│ ├ src        │  ┌──────┬───────────────────────────┐  │
│ │ ├ a.py     │  │   1  │ import os                 │  │

│ └ tests      │  │   3  │     ...                   │  │
│              │  └──────┴───────────────────────────┘  │
└──────────────┴────────────────────────────────────────┘
   固定左侧（<details> 折叠，无 JS）    右侧：锚点 + 行号 + 高亮
```

### 4.2 交付说明片段

```markdown

- 产物：`源码.html`（单文件，<n> MB）
- 命令：`python scripts/source_pack.py <dir> -o 源码.html --title "<项目名>"`
- 范围：扩展名 <清单>；排除 <目录清单>
- 统计：文件 <n> 个 / 总行 <n> 行

```

## 五、反例

**反例 1：引 CDN 做高亮**
> `<script src="https://cdn.jsdelivr.net/npm/highlight.js"></script>`

错在哪：断网打不开、内网打不开、半年后 CDN 挂了打不开。交付物必须自包含。本 Skill 的高亮是纯 CSS 类，由打包器在生成时打好，不依赖运行时 JS。

**反例 2：把整个仓库塞进去**
> 打包了 `node_modules` 与 `.git`，产物 400 MB。

错在哪：打不开、没法读、也没意义。排除目录是硬要求，`.git` 里还有历史凭证风险。

**反例 3：行号是「假的」**
> 行号由 CSS counter 生成，但空行被压缩掉了，导致行号与真实行错位。

错在哪：源码汇总的用途之一是「按行号回指」（审查报告、整改对照表都用 `file:line`）。行号失真 = 交付物失去索引价值。判据：页面行数必须等于源文件行数。

**反例 4：打包后在 HTML 里改源码**
> 发现一处笔误，直接在 HTML 里改了。

错在哪：HTML 是源码的**快照**，改了它就和仓库不一致，后续引用 `file:line` 全部对不上。要改就改源码再重新打包。

**反例 5：只打包主目录，漏了配置与测试**
> 只打 `src/`，不含 `tests/`、`config/`、`README`。

错在哪：审查方与接手人看不到测试与配置，无法判断质量。默认应含全部文本文件，靠白名单与排除目录控制，⛔ 不靠「随手选几个目录」。

## 六、与上下游的衔接

**允许收工的条件（全满足）**
1. `source_pack.py` rc=0。
2. 四条验证命令结果符合预期（外链 0 / 文件数对得上 / 行号元素 > 0 / 体积可接受）。
3. 人工抽验 3 处跳转 + 2 处折叠正常。
4. 交付说明写明范围与统计。

**必须退回的情况**
- 文件数对不上 → 回 S7 确认是否漏提交文件，或修白名单重打。
- 产物过大（> 30 MB）→ 按模块分多次打包（`--ext` + `--exclude` 缩范围），⛔ 不许硬塞。
- 发现源码与 HTML 内容不一致 → 重新打包，⛔ 不许改 HTML。
