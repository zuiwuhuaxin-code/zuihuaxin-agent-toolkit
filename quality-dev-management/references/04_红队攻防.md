# S4 红队攻防

> 位置：S3 编码自测通过之后，S5 蓝队防守之前。
> 本阶段唯一不可替代的价值：**主动扮演攻击者，把「可能出事」变成「有编号、有位置、有影响的缺口」**。⛔ 只讲概念不算做完。

## 一、目标与判据

| 目标 | 判据（可观察） |
|---|---|
| 覆盖八个攻击面 | 每个面至少一条 G/E/A/I/F 记录，或显式写「本面无缺口 + 判断依据」 |
| 缺口可追踪 | 编号 `E-xx` 唯一且连续；每条能回读到代码位置 |
| 攻击有路径 | 每条 A 列写清「从哪进 → 做什么 → 得到什么」，不是「可能被利用」 |
| 有加固 | 每条 E 对应至少一条 F，F 落到 `file:line` 或配置项 |
| 多轮有递增 | 轮次表能看出「本轮新缺口源自上轮哪条加固」 |
| 闸门定档 | 每条闸门标 `block` / `warn`，⛔ 无 silent-off |

闸：`acceptance_gate.py` 检查红队报告含「五列对照表」与「轮次」两节，且 `E-` 出现次数 ≥ 攻击面数。rc=0 才进 S5。

## 二、输入

1. S3 的代码与自测记录（尤其错误处理路径、鉴权入口、IO 边界）。
2. PRD 里的权限模型、数据分级、外部依赖清单。
3. 部署形态（本地 / 内网 / 公网）——决定攻击面权重，但不决定是否要列。

## 三、攻击面清单（八面，逐面扫，⛔ 不许跳面）

| # | 攻击面 | 扫什么 | 典型缺口 |
|---|---|---|---|
| 1 | 认证授权 | 登录、会话、token 生命周期、权限判定点 | 无鉴权、token 不过期、权限校验写在前端 |
| 2 | 输入校验 | 一切外部输入：参数、文件、URL、header、来自第三方的数据 | 未校验长度/类型/枚举、模糊匹配当校验、只在前端校验 |
| 3 | 密钥凭证 | 硬编码 key、日志打印凭证、配置明文、示例文件残留真实值 | 源码里 `password=`、`.env` 提交、错误信息回显密钥 |
| 4 | 文件路径 | 上传、下载、导出、临时文件、路径拼接 | `../` 穿越、绝对路径可控、符号链接跟随、临时文件竞态 |
| 5 | 越权 | 水平（同角色他人数据）/ 垂直（低角色做高角色事） | 只校验登录不校验归属、ID 直接取自请求 |
| 6 | 日志泄露 | 记了什么、记到哪、谁能读 | 日志含手机号/身份证/完整报错栈、日志文件可被 web 访问 |
| 7 | 依赖供应链 | 依赖来源、版本锁定、安装来源 | 无 lock 文件、从非官方源装、依赖版本过旧且有已知 CVE |
| 8 | 配置错误 | 默认配置、调试开关、跨域、权限位 | debug 上线、CORS `*`、默认口令未改、目录可列 |

**扫面优先级**：按数据分级与暴露面排。公网 + 用户数据 → 1/2/5 优先；纯本地工具 → 4/8 优先。⛔ 不许因为「内部用」就跳过认证授权。

## 四、操作步骤

**D1 建模（先想清楚攻击者要什么）**
列资产（数据、能力、凭证）→ 列入口（谁能碰到什么）→ 列信任边界（哪一步开始「相信上游」）。多数缺口都出现在信任边界上。

**D2 逐面扫描**
每个面按「入口 → 数据流 → 判定点」走一遍，把走不通的地方标「无缺口 + 依据」，走通的记成候选缺口。

**D3 填五列**
每条候选补成完整一行：G（对应哪道闸门 / 哪层防线）、E（缺口编号）、A（攻击路径）、I（影响：谁能读到/改到/拿到什么，是否可逆）、F（加固：改哪个文件哪行，或加什么配置）。

**D4 定档（`00_工程规范.md` §七）**
按置信度定档：高置信（确定是漏洞）→ `block`（必须修）；中低置信（可疑、依赖环境）→ `warn`（留痕 + 责任人 + 可升级）。⛔ 没有 silent-off 这一档——任何「先关掉」都必须告警留痕。

**D5 自行加固并留证**
每条 `block` 必须当轮修掉，修完记录 `改后 file:line` 与验证方式（用例 / 命令 / rc）。`warn` 允许挂着，但要有责任人。

**D6 再攻一轮（多轮递增）**
规则：**每轮只针对上一轮加固后的新缺口**。具体做法：
1. 上轮所有 `block` 修完后，重跑上轮的攻击路径 → 期望全部被拦（记 rc / 返回码）。
2. 站在「修完之后多出了什么」的角度找新缺口：新增的校验分支有没有旁路？新增的错误信息有没有泄露？新增的配置文件权限对不对？
3. 收敛判据：某轮新增 `block` 缺口 = 0，且上轮路径全部复验被拦，则可停。⛔ 不许用「轮数到了」当停的理由。

**D7 收口**
出报告 → 交 S5。红队报告里的每条 E 都是 S5 的输入契约。

## 五、输出模板

### 5.1 五列对照表（G / E / A / I / F）

| G 闸门/防线 | E 缺口 | A 攻击路径 | I 影响 | F 加固 |
|---|---|---|---|---|
| G-01 输入校验（应用层） | E-01 上传未校验扩展名 | 上传 `x.php` 到 `/upload` → 直接访问 | 任意代码执行，不可逆 | F-01 `src/upload.py:34` 加白名单 + 拒绝双扩展名（block） |
| G-02 认证（应用层） | E-02 导出接口无归属校验 | 改 `id` 为他人 id → 拿到他人数据 | 水平越权，数据泄露 | F-02 `src/export.py:61` 加 `owner==user.id` 判定（block） |
| G-03 密钥管理（CI + 制品扫描） | E-03 测试配置残留真实 key | 读仓库历史拿到 key | 凭证泄露，需轮换 | F-03 移除并改用环境变量 + 轮换（block） |

**列定义不许含糊**：
- **G** = 这条缺口本该被哪道闸/哪层防线挡住（对不上任何闸 = 该闸缺失，本身就是一条缺口）。
- **E** = 缺口编号，全局唯一，S5/S7 直接引用它。
- **A** = 攻击路径，写「输入 → 处理 → 结果」三步，⛔ 不写「可能被攻击」。
- **I** = 影响，必须回答「谁受损、损到什么、可不可逆」。
- **F** = 加固，必须是可执行动作 + 位置 + 档位。

### 5.2 攻击面覆盖表（防漏面）

| 面 | 结论 | 依据 | 关联 E |
|---|---|---|---|
| 1 认证授权 | 有缺口 | 见 E-02 | E-02 |
| 2 输入校验 | 有缺口 | 见 E-01 | E-01 |
| 3 密钥凭证 | 有缺口 | 见 E-03 | E-03 |
| 4 文件路径 | 无缺口 | 全部路径由白名单枚举生成，无用户输入拼接（`src/store.py:20-45`） | — |
| 5 越权 | 有缺口 | 见 E-02 | E-02 |
| 6 日志泄露 | 无缺口 | 日志字段白名单 `src/log.py:8`，仅记 id 与耗时 | — |
| 7 依赖供应链 | 有缺口 | 无 lock 文件 | E-04 |
| 8 配置错误 | 有缺口 | debug 默认开 | E-05 |

### 5.3 轮次表（多轮递增的证据）

| 轮次 | 针对上轮哪条加固 | 复验上轮路径 | 本轮新增 E | 本轮新增 block 数 | 收敛？ |
|---|---|---|---|---|---|
| R1 | —（首轮全扫） | — | E-01~E-05 | 3 | 否 |
| R2 | F-01 白名单 | 上传 `.php` → 拒绝（rc=1 用例绿） | E-06 双扩展名 `a.jpg.php` 绕过 | 1 | 否 |
| R3 | F-06 双扩展名判定 | `a.jpg.php` → 拒绝 | 无 | 0 | **是** |

**收敛判据**：新增 block = 0 **且** 上轮路径复验全拦。两条缺一不可。

## 六、反例

**反例 1：只有结论没有编号**
> 「系统可能存在 SQL 注入、XSS 等风险，建议加强输入校验。」

错在哪：没有 G（哪道闸）、没有位置（哪行）、没有 A（怎么打）、没有 F（怎么修）。这种报告在 S5 无法承接、S7 无法整改、S6 无法复核，等于没做。

**反例 2：五列填成同义反复**
> A 列写「攻击者利用 E-01 进行攻击」，I 列写「存在安全风险」。

错在哪：A 与 I 都是空转。A 必须写清输入与路径，I 必须写清受损对象与可逆性。

**反例 3：多轮 = 把上一轮抄一遍**
> R2 又列 E-01~E-05，没有新编号。

错在哪：轮次的意义是「加固后有没有新洞」。抄一遍既不能证明加固有效（没有复验结果），也不能发现新缺口，纯凑格式。

**反例 4：把中低置信的猜测全部标 block**
> 五条推测全标 block，结果三条是误报。

错在哪：误报率高的闸会被关掉，一旦被关就等于没闸（`00_工程规范.md` §七「置信度 → 档位」中低置信退 warn 的理由）。⛔ 不许自行提级。

**反例 5：只扫公网面，跳过内部面**
> 「内网系统，无需考虑认证授权与越权。」

错在哪：内部系统的横向移动正是最大风险源；且「内部」不等于「可信」，配置错误面（debug、默认口令）恰恰在内网高发。

**反例 6：加固写成「加强校验」**
> F 列：「加强文件类型校验。」

错在哪：不可执行、不可核。必须写「在 `file:line` 加什么判断，拒绝什么输入，用什么用例验」。

## 七、与上下游的衔接

**允许进入 S5 的条件（全满足）**
1. 八个面都有结论（有缺口或明确无缺口 + 依据）。
2. 五列表每行五列非空，`E-` 编号唯一连续。
3. 所有 `block` 级缺口已修，且有「复验被拦」的记录。
4. 剩余 `warn` 项有责任人与升级条件。
5. 轮次表至少一轮有复验结果；若只有一轮，须写明「为何一轮即收敛」。
6. 闸 rc=0。

**必须退回的情况**
- 扫面时发现某个面完全没有防线（连闸都没有）→ 退回 S2 补任务，属设计缺失而非实现缺陷。
- 加固需要改 PRD 定的行为（例：PRD 要求明文导出，安全要求脱敏）→ 退回 S1 冲突清单，⛔ 不许红队自行改需求。
- 复验发现加固无效 → 留在 S4 重修，⛔ 不许带无效加固进 S5。
