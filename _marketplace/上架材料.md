## 2. 商品页填什么（可直接复制）

### 2.1 资产一：`pm-prd-generator`

| 字段 | 内容 |
|---|---|
| 技能 ID（name） | `pm-prd-generator` |
| 展示名 | **可评审 PRD 生成器**（2026-10-25 15:12 改：原名被平台已有资产占用） |
| 英文展示名 | PRD Generator |
| 版本 | 1.2.1 |
| 作者 | 醉花心 |
| 建议类目 | 办公协同（若只能选开发工具类，选开发工具） |
| 一句话简介（zh） | 把一段口头需求推进到可评审 PRD。六阶段流水线，每阶段有独立判据与禁止项，附命令行自查脚本（8 项检查、四档退出码）。 |
| 一句话简介（en） | Turn a verbal product idea into a review-ready PRD through a six-stage pipeline. |

**适合谁**
写 PRD 的产品经理、要接需求的独立开发者、被「一句话需求」坑过的人。

**需要买家准备什么**
一段产品想法（越具体越好，一两句话也行）。不需要装任何第三方库。

**交付什么结果**
一份 `PRD.md`（八项要求逐条可核：背景 / 目标 / 用户与场景 / 功能清单 / 字段与规则 / 边界与不做 / 验收标准 / 风险）+ 需要时一份单文件 HTML 原型；末尾附自查结论与未解决项清单。

**有什么限制**（照抄进「限制」栏）
- 不写代码，不做 UI 视觉稿，不出技术架构方案（那是 `quality-dev-management` 的活）。
- 需求信息不足时**会先追问，不猜**。它不会替你编用户调研数据。
- 自查脚本检的是**文档结构完整性**，检不出「业务判断对不对」—— 那得人来定。

**试试这样问我**（商品页示例，3 条）
1. 帮我给「公众号排版器」写一份 PRD
2. 这段需求太模糊，先做需求澄清和十个关键问题
3. 把这个 PRD 自查一遍，列出哪些条款第三方核不了

| 版本 | 1.2.1 |

| 一句话简介（zh） | 从 PRD 到可验收代码的八阶段管理流程。每阶段产出必须带机器可判证据，红队攻防与独立审查分离施工方，最终以验收闸门 rc=0 收工。 |
| 一句话简介（en） | An eight-stage workflow from PRD to verifiable code, closing only when the acceptance gate returns rc=0. |

**适合谁**
独立开发者、小团队的技术负责人、请 AI 写代码但验收靠「看着差不多」的人。

**需要买家准备什么**
一份需求文档（不一定是本店另一个 Skill 产出的，手写的也行）；一个本地代码目录。

**交付什么结果**
项目评估报告 → 施工计划 → 带自测的代码改动 → 红队问题清单（附 `file:line`）→ 蓝队整改对照表 → 独立审查报告 → 闭环记录 → 一份源码汇总 HTML。最终跑验收闸门拿 `rc=0`。

**有什么限制**（照抄进「限制」栏）
- **不替你决定要不要做**。它评的是「能不能验收」，不是「值不值得做」。
- 证据依赖本地命令真跑；如果你的环境缺 python 或命令不可用，闸门会**降级**并明说降了多少，不会假装通过。
- 红队/蓝队的价值取决于给的上下文。塞一个空目录进去，它只能告诉你「没东西可审」。

**试试这样问我**（商品页示例，3 条）
1. 帮我评估这个项目，出一份施工计划
2. 跑一遍红蓝攻防，把这份代码的问题挑出来
3. 把源码整理成一份 HTML 汇总

## 3. 提交步骤（照这个顺序，顺序错了会白跑）

1. **认证**：打开 `open.workbuddy.cn` → 登录 → 按页面选个人/企业认证。
   个人要身份证 + 实名手机号 + 邮箱 + 人脸核验。
2. **上传资产**：左侧「发布管理 → 技能」→ 创建资产 → 上传 §1 的 zip。
   ⚠ 一次传一个 zip，**不要把两个打成一个大包**（平台按单 skill 解析）。
3. **填商品页**：按 §2 复制。类目、付费方式、原创声明在同一步。
4. **提交审核**。审核通过后**先别发布上线**，停在「待发布」——
   原因见 §4 顺序陷阱。
5. **开通收款**：「收入变现 → 开通收款账户」。**前置条件：已有 ≥1 个通过审核的技能/专家**
   + 已完成认证 + 无违规记录。填资料 → 后台审核 → 微信扫码签约。
6. **设价再发布**：签约后回到资产，设付费模式与价格 → 发布。

**如果 zip 解析报错**：把平台给的错误原文发我，我照错误改包重打。
实在卡住可邮件 `openworkbuddy@tencent.com`，或扫开放平台首页底部二维码进社群。

## 4. 两个规则陷阱（会直接决定收入）

**① 付费方式发布后不可更改。** 一次性买断 ↔ 按月订阅，选错了只能下架重发。

**② 内测阶段，已发布的免费资产暂不支持转付费。**
所以顺序必须是：**审核通过 → 留「待发布」→ 开通收款 → 设价 → 再发布**。
⛔ 别想着「先免费上架攒用户，以后再改收费」—— 这条路现在走不通，得重新发一个资产。

其余数据：内测期平台服务费 **1%**；单个资产价格 1–9999 元；付费资产会**加密并在云端运行**。

### 定价建议（不是定论，你拍）

| 资产 | 建议 | 理由 |
|---|---|---|
| 可评审 PRD 生成器 | 一次性 39–69 元 | 交付边界清晰（一份 PRD），买家一眼能判断值不值；订阅没有持续更新理由 |
| 研发质量八阶段管理 | 一次性 99–149 元 | 覆盖整条开发链路，价值密度高；但**买家一次买断后不会再付第二次**，价格别抬到需要「持续服务」的程度 |

⚠ 这两个都**不适合按月**：它们不含服务端能力、不含持续更新的数据源，按月订阅等于承诺你没打算兑现的东西。
